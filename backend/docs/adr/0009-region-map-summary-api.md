# ADR 0009. Region 지도 요약 API와 테스트 범위

- 상태: 채택
- 날짜: 2026-08-11
- 관련: ADR 0004, ADR 0008, 이슈 #24, #25, #26

---

## 문제

국가, 시도, 시군구마다 별도 요청 파라미터를 추가하면 Region 계층이 늘어날 때마다 API 계약이 변경된다. 반면 `region_code`는 국가별로 중복될 수 있으므로 코드 하나만으로 Region을 식별할 수 없다.

또한 지도 색칠 API는 기록이 있는 지역뿐 아니라 0건인 지역도 식별할 수 있어야 한다. 그래야 클라이언트가 색칠 단계 0을 표현하고 후속 하위 Region 요청에 사용할 식별자를 얻을 수 있다.

## 결정

지도 요약 API는 Region 계층을 기준으로 구성한다.

- 최초 `GET /api/v1/travel-records/map-summary/regions` 요청은 모든 국가 Region의 요약을 반환한다.
- 후속 이슈에서 같은 URI에 `parentRegionId`를 추가해 특정 Region의 직속 자식 요약을 조회한다.
- 응답은 후속 요청용 `regionId`와 로컬 지도 매칭용 `regionCode`를 함께 제공한다.
- 클라이언트는 `regionId`를 행정 코드처럼 영구 저장하지 않고 API 탐색에만 사용한다.
- 기록이 없는 Region도 `count = 0`, `level = NONE`으로 반환한다.
- 색상 단계는 비율이 아닌 고정 기록 수 구간이므로 `NONE`, `LOW`, `MEDIUM`, `HIGH` enum으로 표현한다.
- 국가 집계는 국가 Region 자체와 `root_id`가 해당 국가인 모든 하위 Region의 기록을 포함한다.

## 조회 방식

국가 목록과 현재 회원의 기록 수를 하나의 집계 쿼리로 조회한다. 엔티티 그래프를 순회하지 않고 스칼라 프로젝션을 반환해 N+1 쿼리를 방지한다.

## 테스트 범위

- 색상 단계 정책은 Spring 없이 단위 테스트한다.
- 서비스는 Repository를 대역으로 둔 단위 테스트로 회원 검증과 응답 변환을 확인한다.
- 컨트롤러는 MVC 슬라이스 테스트로 HTTP 계약을 확인한다.
- Repository 쿼리와 Flyway 스키마의 호환성만 MySQL Testcontainers 통합 테스트로 확인한다.
- 서비스 전체 Spring 통합 테스트는 같은 동작을 중복 검증하고 실행 비용이 크므로 작성하지 않는다.

## 결과

- Region 단계가 추가돼도 계층별 파라미터를 새로 만들 필요가 없다.
- 중복 가능한 행정 코드가 API 조회 식별자로 단독 사용되지 않는다.
- 지도 코드와 DB 식별자의 역할이 분리된다.
- 운영 MySQL과 같은 DB에서 집계 쿼리를 검증하면서도 대부분의 테스트는 빠르게 유지한다.
